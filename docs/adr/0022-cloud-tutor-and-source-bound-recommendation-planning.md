# ADR-0022：云端递进 Tutor 与来源约束的智能任务规划

- 状态：`Accepted`
- 日期：`2026-07-23`
- Owner：项目 Owner + API/Flutter/Web/AI 负责人
- 决策者：项目 Owner（用户；在真实 iPad 体验后明确要求整改 L1/L2，并要求任务推荐分析教材、错题频率、具体练习和未来计划）
- 关联：`PLAN-0017`、`ADR-0004`、`ADR-0020`、`ADR-0021`、`FR-005`、`FR-019`、`FR-020`
- 替代/被替代：细化 ADR-0020/0021 的 Tutor 与推荐实现；不改变家长审批、已发布教材、ReviewPolicy 和图片安全边界

## Context

当前 L3 完整解答使用 NewAPI，因此能理解“多人同时经历同一段时间”等语义；L1/L2 却使用有限关键词模板，真实体验出现与题意无关的“增减、比较、平均分”提示。当前推荐同样只读取到期错题或教材第一个小节，不能消费 PDF 页级内容、错题频率，也不能向孩子提供具体题目。

仅增加更多关键词无法覆盖小学应用题的事件关系；直接把整本 PDF 或全部儿童历史发送给模型又违反最小外发、版权和 Prompt 注入边界。需要在云模型质量与来源约束之间建立明确架构。

## Decision Drivers

- L1/L2 必须真正理解当前题目，并严格递进且不泄露答案。
- 家庭已部署 NewAPI，云模型可以承担文本推理；本地硬件不作为 Tutor 模型运行前提。
- 推荐必须使用全部开放/到期错题和已发布教材，而不是手工小节占位。
- 教材题、页码、错题频率和计划日期必须可追溯，模型不能静默伪造来源或正式下发任务。
- PDF、图片、对象键和无关儿童历史不得外发；文档内容仍是不可信数据。

## Considered Options

1. 继续扩充本地关键词模板。成本低，但无法稳定理解同时、包含、对应、守恒等关系，真实体验已经证明不可接受。
2. 把整本 PDF、全部错题和自由 Prompt 交给云模型，让模型直接创建任务。质量上限较高，但扩大版权/儿童数据外发，无法验证来源，且绕过家长控制。
3. 本地全量扫描与统计、云端有界规划、服务端来源回填与验证。Tutor 使用已确认题目和最小教材片段；推荐模型只选择服务端签发的候选 key，正式 Task 仍由家长批准。

## Decision

选择选项 3。

1. NewAPI Adapter 增加文本 Tutor Hint 方法。L1/L2 使用固定 JSON Schema、温度 0、已确认题目、作答状态、前一级提示和最多 3 个已发布教材片段；不发送图片、对象键或整本教材。
2. L1 目标为题目特有的关键关系；L2 必须引用服务端读取的同题 L1 并增加方法/表示/第一步脚手架。服务端拒绝最终答案、完整步骤、明显结论句、已知答案泄露和 L1/L2 重复；失败回退题型化确定性模板。
3. 推荐引擎在本地遍历最新已发布 Snapshot 的全部 chunks，并读取全部开放错题及到期状态。它计算题型/知识点提示、频次、到期优先级和全文相关度，再只选择有界候选发送给 NewAPI。
4. NewAPI 可以自由决定候选组合、未来 7 天日期、题量、预计时间、标题和解释，但只能返回服务端提供的 opaque source key。教材题正文、页码、Snapshot/Chunk ID、错题 ID 和最终展示的知识点均由服务端按本地来源回填；模型提供的知识点只作非事实建议，不入库。
5. 已发布教材中的具体练习可以在同一家庭的孩子端显示；推荐和 Task 保存最小题目正文及来源锚点，不复制整页或整本教材。无法从 chunk 提取完整题目时不生成教材题。
6. TaskRecommendation 继续为派生候选，默认 `pending`；家长批准后才创建正式 Task。AI 不直接创建 Task、不修改 ReviewSchedule、不判定永久掌握。
7. 新增推荐/任务字段采用向前兼容迁移。旧记录保留并显示为历史来源不完整记录；新生成路径不再创建“按教材练习一小节”等占位内容。

## Consequences

### Positive

- L1/L2 与 L3 共享云模型的题意理解能力，同时保留教学层级和答案门禁。
- 推荐真正消费错题和 PDF 内容，并能把具体题目、页码和时间计划交付给孩子端。
- 本地扫描整本、云端只看候选，降低版权内容、Prompt 注入和成本暴露。
- source key 与服务端回填阻止模型把新编题伪装成教材原题。

### Negative / Trade-offs

- L1/L2 和推荐依赖 NewAPI 可用性、延迟与费用；必须保留降级和成本记录。
- 规则化教材题抽取对复杂排版、跨页题和扫描 PDF 有限制；低完整度候选必须舍弃。
- Task/Recommendation/OpenAPI/客户端和迁移同时变化，必须成对部署。

### Risks and Mitigations

- 答案泄露：严格 Schema、已知答案字符串检查、结论/完整等式检查、L2 差异校验和固定 eval。
- 模型伪造来源：只接受 allowlist source key，正文和 ID 由服务端回填。
- 整本材料外发：本地扫描全量 chunks，Provider 请求只含有界候选和必要错题摘要。
- 任务过量：最多 5 条、未来 7 天、每日上限 3 条、家长批准。
- Provider 故障：Tutor 回退确定性模板；智能推荐返回明确不可用，不生成低质量占位。

## Compatibility and Migration

- 新增 `0024_intelligent_recommendations`，为 Recommendation/Task 增加可空来源和计划字段；旧客户端忽略新增响应字段。
- 部署顺序为迁移 → API → Web → Flutter。回滚应用时保留新增列和既有记录；关闭 Provider/智能推荐不删除审批与任务事实。
- 旧推荐历史继续可读；去重从“一个错题永远一条”调整为“同一内容最多一个 pending”，允许在新的计划周期重新推荐同一错题。

## Validation

- 固定题覆盖同时、增减、比较、平均、分数和有作答错步；检查 L1 相关性、L2 递进和答案泄露。
- 推荐覆盖多道同类错题频次、到期/未到期混合、整本多页教材、具体题抽取、页码、7 日计划、每日上限、Provider Schema/伪造 key/超时和重复请求。
- 覆盖未发布/跨孩子/跨家庭 chunk、Prompt 注入文本、无完整题目、无 Provider、审批/忽略、批准生成 Task 和孩子端多任务展示。
