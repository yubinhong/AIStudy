# ADR-0020：教材驱动的数学错题学习闭环

- 状态：`Accepted`
- 日期：`2026-07-18`
- Owner：项目 Owner + 产品/API/Flutter 负责人
- 决策者：项目 Owner（用户；2026-07-18 明确认可该方向和建议并要求落实详细规划；同日确认拍题应同时分析孩子作答，空白表示没有思路并允许从头讲解）
- 关联：`PLAN-0014`、`TODO-016`～`TODO-019`、`PRD-001`、`ADR-0003`、`ADR-0004`、`ADR-0015`
- 替代/被替代：不替代既有 ADR；将原先后置的教材导入、详细错题讲解和复习调度提升为数学首科产品主线

## Context

当前实现以家长创建今日任务、孩子拍题、确认题目、请求 1～3 级提示并以 `needs_review` 完成会话为主。它已经验证了 Capture、VerifiedQuestion、TutorTurn、Attempt 和周报的最小技术链路，但没有教材导入/发布、正式错题记录、复习计划或任务推荐，也没有孩子端“数学 → 错题讲解 / 复习错题 / 今日任务”的主信息架构。

项目 Owner 明确产品应从当前年级、学期和家庭教材开始：孩子拍摄做错题目，系统按已知知识点给出准确且适龄的详细过程，形成错题合集；复习模式再逐题过关；今日任务由家长安排或系统依据错题建议。该产品不是通用拍题搜答案，也不是只有任务列表的 Tutor 外壳。

实施澄清（2026-07-23）：后续代码虽已出现 Mistake/Review 表与基础接口、教材多文档上传和三级提示，但代码审计确认它们尚未满足本 ADR：拍题讲解完成未原子创建 MistakeRecord/ReviewSchedule，复习未加载实际题目或追加重新作答证据，PDF/DOCX/PPTX 未解析，L1/L2 多数只是浅层文案而非稳定教学递进。PLAN-0016 负责收口；教材解析的格式、依赖和隔离方案由 Proposed ADR-0021 决定。在这些验收通过前不得声称本闭环已实现。

## Decision Drivers

- 讲解必须与孩子当前年级、教材版本和已确认知识范围一致，而不是依赖模型的无来源记忆。
- 拍题照片通常同时包含题目和孩子作答；系统必须保留“有作答”或“确认空白”的真实学习状态。未拍到答题区与答题区空白是两种不同状态。
- 错题需要形成可追溯、可复习、可删除/导出的长期学习对象，而不是会话上的一个布尔标记。
- 复习和任务安排要可解释、可复算、可由家长控制，不能由 AI 静默决定掌握度或给孩子无限任务。
- 必须保留图片脱敏、题目人工确认、Household/Child 授权、追加写 Attempt 和 Provider Adapter 等既有安全边界。

## Considered Options

1. 保持任务优先：继续以家长任务和分级提示为中心，只把 `needs_review` 展示成错题清单。
2. 建成拍题搜答案：孩子上传任意题目后直接由云模型给完整答案，简单保存历史图片。
3. 建成教材驱动的错题学习闭环：家长发布知识范围，错题讲解要求确认题目和作答状态（有作答或确认空白），形成 MistakeRecord/ReviewSchedule，并据此产生复习和任务建议。

## Decision

选择选项 3。

1. 数学是首个可用学科。孩子端先显示学科，再在数学内提供三个一级入口：错题讲解、复习错题、今日任务；未来学科通过插件扩展，不能污染数学核心模型。
2. 家长为每个孩子建立按学年/学期/年级/出版社版本的 CurriculumAssignment，导入家庭有权使用的教材或课程资料。解析结果必须带材料版本和页码/段落来源，先由家长审核并发布不可变 CurriculumSnapshot，未发布内容不能成为 Tutor/任务依据。
3. Capture 路线继续遵循 ADR-0015/0018：图片安全上传、脱敏、单一云视觉 Provider 解析并人工确认形成 VerifiedQuestion。云视觉还必须将题目与孩子作答分开提取，产生 `worked/blank/unclear/answer_area_missing` 作答状态候选；孩子确认/修正后才形成 AttemptEvidence。图片解析不直接输出讲解或错题事实。
4. 错题讲解必须先取得 VerifiedQuestion 和已确认作答状态。`worked` 时保存有限结构化答案/步骤，讲解优先定位第一个可验证错误；答题区可见且经用户确认空白时，记录 `blank_confirmed/no_approach` 并允许从题意和知识点开始完整讲解，不强迫再作答。`unclear` 或 `answer_area_missing` 不得自动当作空白，必须重拍或手工确认。普通今日任务与复习仍先作答、再提示。
5. 完整讲解至少包含题意、已知/所求、知识点、可能错因、逐步过程、最终答案、可确定的计算/单位校验和一道变式练习，并引用所用 CurriculumSnapshot/KnowledgePoint。低置信度、错版、超纲或校验失败必须阻断并请求校正/家长复核。
6. MistakeRecord 引用 VerifiedQuestion、首次已确认 AttemptEvidence（作答或空白）、错因/无思路、知识点、讲解版本和状态。ReviewSchedule 使用版本化确定性 Policy，AI 不直接决定到期或永久掌握；每次复习结果追加写，错误可重新激活。
7. 复习默认展示今日到期队列，同时提供复习全部；每题先隐藏答案和完整讲解并要求重新作答。
8. 今日任务区分家长安排、到期复习和系统建议。到期错题可在家长开启设置后确定性下发；基于薄弱知识点的系统建议默认必须由家长审核。首批不允许 AI 无审核生成并下发全新题目。
9. 教材文件、解析内容和模型输出均为不可信输入。Tutor 只发送完成当前讲解需要的最小已发布片段，不发送整本教材、对象 URL、其他孩子数据或无关历史；导入内容中的指令不得进入系统 Prompt。

## Consequences

### Positive

- 产品价值从“能拍题”变为有教材依据、真实作答状态证据和复习结果的闭环。
- 讲解模式与练习模式边界清楚，既能满足错题的详细过程，又不会让日常任务变成直接搜答案。
- 复习与任务建议可追溯到错题、知识点和教材来源，家长能够理解和控制。
- 复用现有 Capture/VerifiedQuestion/Attempt/TutorTurn，避免重建平行的数据链路。

### Negative / Trade-offs

- 需要新增内容导入/审核、知识结构、错题、复习和推荐领域及多份迁移/契约，实施规模明显增大。
- 家长导入和审核教材有前置工作；完全自动导入会降低可信度，因此首版接受人工确认成本。
- 保存孩子结构化作答/空白状态和教材材料扩大了 Confidential/版权数据范围，需要更严格的保留、删除、备份和最小日志。
- “精确讲解”仍不能作绝对保证，需要固定数学 eval、确定性校验和人工纠错入口。

### Risks and Mitigations

- 风险：教材解析错误或版本错配；缓解：版本化草稿、来源定位、家长发布、错版/超纲阻断和不可变 Snapshot。
- 风险：导入材料含 Prompt 注入；缓解：材料只作为结构化数据/引用，固定 Prompt 边界，不执行文档指令。
- 风险：AI 对错误原因过度推断；缓解：区分孩子自述、规则推断和模型建议，低置信度要求家长/孩子确认。
- 风险：浅色铅笔字、擦改痕迹或未拍到答题区被误判为空白；缓解：Schema 区分四种作答状态、返回区域覆盖/置信度、用户确认，不清/缺失时重拍而不自动空白。
- 风险：复习或任务过量；缓解：确定性队列、家庭可配置上限、家长审核和可解释来源。
- 风险：版权内容被复制/外发；缓解：家庭授权声明、私有存储、最小片段调用、禁止公共库/仓库/评测集和导出范围控制。

## Compatibility and Migration

- 兼容性：扩展现有 Task/StudySession/Attempt/TutorTurn，新增 Curriculum/Mistake/Review/Recommendation 表和合同。当前 `needs_review` 只可迁移为待补全候选，不能推断不存在的错误答案、空白状态、知识点或掌握度。
- 迁移步骤：先完成 PLAN-0012 安全上传；扩展数据库/OpenAPI → 家长课程与教材发布 → Flutter 三入口/错题讲解 → 错题本与复习 → 任务建议；每阶段由独立开关控制并成对部署客户端/服务端。
- 回滚：优先前滚修复；回退应用时保留新表、已发布 Snapshot、VerifiedQuestion、Attempt 和审批事实，不破坏性 downgrade。关闭 Provider 后仍可手工录入错题、查看既有讲解和执行已有复习队列。

## Validation

- 用 synthetic 教材覆盖文本/扫描 PDF、重复文件、恶意指令、错版、低置信度、来源缺失、版本更新、审核发布和跨家庭访问。
- 用固定小学数学题覆盖识别校正、多步作答、真实空白、浅色铅笔字/擦改、答题区未入镜、作答状态人工修正、有作答错因定位、空白从头讲解、知识点匹配、完整解法、计算/单位校验、超纲阻断、模式绕过、Provider 失败和成本。
- 覆盖 MistakeRecord 幂等创建、作答状态未确认拒绝、`blank_confirmed` 作为有效证据、导出/删除、ReviewSchedule 并发/重试/重激活和版本重算。
- Flutter 覆盖学科/三入口、零数据空状态、到期/全部复习、逐题过关、弱网恢复、横竖屏、键盘/读屏和实体设备相机权限。
- 任务建议覆盖家长批准/拒绝、到期复习确定性生成、重复建议去重、每日上限和每条任务的来源解释。
