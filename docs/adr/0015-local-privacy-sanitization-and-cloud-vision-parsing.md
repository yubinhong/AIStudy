# ADR-0015：本地隐私脱敏与云端视觉解析

- 状态：`Accepted`
- 日期：`2026-07-15`
- Owner：`项目 Owner（用户）`

- 替代/被替代：替代 `ADR-0012` 的默认“本地 OCR 完整解析题目”路线；保留其已实现代码和供应链记录作为迁移事实
- 批准记录：项目 Owner 提供架构讨论并明确决定“OCR 只用于脱敏，云端模型解析照片”。具体云 Provider、法域、数据处理条款、区域、预算和评测阈值仍是发送真实儿童图片前的硬性阻塞项。

## Context

当前 Capture 路线已实现本地 PaddleOCR 的文字/公式解析、候选确认、Job Ledger 和固定 synthetic 评测。实际家庭低频拍题中，云端多模态模型对公式、几何图、表格、插图和手写答案的完整理解更适合承担题目结构化；继续让本地 OCR 同时负责隐私、版面和题目语义，会增加模型体积、运行维护、结果合并和错误传播成本。

图片属于 Restricted 数据。把原图直接发给云端不可接受；仅依赖 OCR 自动识别敏感内容也不能保证识别潦草手写姓名、真实人脸、二维码或背景中的家庭信息。因此需要把“本地脱敏”和“云端解析”拆成两个独立、可阻断、可审计的信任边界。

## Decision Drivers

- 原始图片、儿童身份和家庭环境不得离开家庭控制的存储边界。
- 云端视觉能力应负责完整题目理解，但其输出不能直接成为学习事实或 Tutor 输入。
- 自动脱敏不是绝对保证；低置信度、无法安全裁剪或用户未确认时必须阻断外发。
- 业务代码不得绑定特定云厂商响应；图片不能在多个 Provider 之间静默广播。
- 已实现的 OCR/OpenAPI/迁移不能被静默重解释或破坏性删除。

## Considered Options

1. 保持 ADR-0012：本地 OCR 完整解析题目，只把确认后的文字发送给云端 Tutor。
2. 原图直接发送云端多模态模型，由 Provider 同时完成隐私判断、题目解析和讲解。
3. 本地 `PrivacySanitizer` 生成不可逆脱敏副本，用户确认后由单一获批云端视觉 Provider 结构化解析；确认后的结构化题目再进入独立 Tutor 调用。

## Decision

选择选项 3，并采用以下强制边界。

### 1. 本地 PrivacySanitizer

原图只进入家庭控制的 API/Worker 与私有 MinIO，不向云端暴露对象 URL。`PrivacySanitizer` 依次执行：

1. App 单题裁剪并展示预览；P1 继续保持单题范围，多题分割仍是后续能力。
2. 服务端校验 JPEG/PNG、大小、哈希、容器头和完整像素，按 EXIF 方向旋转后重新编码，移除 EXIF、GPS、设备、时间和缩略图元数据。
3. 本地 OCR 只输出文字框和置信度，用于定位“姓名、学校、班级、年级、学号、考号、座位号、电话、地址、签名”等敏感标签及相邻值；不得把 OCR 题目文本作为最终题目解析结果。
4. 本地规则检测手机号、身份证号、邮箱、长学号和地址等上下文相关模式；题目中的人物名和普通数字不得仅因模式命中而遮挡。
5. 本地视觉检测真实人脸、二维码和条形码。大面积人脸、身份证号、无法区分真实人脸与教材插图、或脱敏置信度不足时设置 `safe_to_upload=false`。
6. 敏感区域扩大安全边距后使用实色块不可逆覆盖，并把像素重新编码为全新 `sanitized_derivative`；禁止用可逆模糊、只保存遮挡坐标或转发原文件。

输出只包含版本化的安全元数据，例如 `safe_to_upload`、`requires_confirmation`、敏感类型枚举、遮挡区域数量、人脸/二维码标志、规则版本和临时脱敏对象引用。不得记录 OCR 识别出的姓名、联系方式、完整题目或遮挡前像素。

### 2. 用户确认与外发门禁

自动脱敏后必须展示脱敏副本，提供“确认并识别、重新裁剪、手动涂抹”。只有同时满足以下条件才允许外发：

- `safe_to_upload=true`；
- 服务端保存的脱敏规则/Schema 版本仍有效；
- 用户已对当前脱敏副本的不可逆哈希显式确认；
- 请求使用获批 Provider、模型、区域、预算和功能开关；
- 原图和任何 MinIO URL 均不在 Provider 请求中。

任何条件不满足时，降级为重新裁剪、手动涂抹或手工录入题目；禁止以“识别效果更好”为由发送原图。

### 3. 云端视觉解析

云端调用通过 Provider Adapter 接收脱敏图片字节和最少必要上下文，只负责输出版本化 `QuestionExtraction` JSON，例如学科、题干、选项、公式、图形/手写标志、检测到的作答、题目区域、置信度和 `needs_confirmation`。Provider 原始响应不直接进入业务库。

每次图片解析只使用一个获批 Provider。超时或失败允许在同一 Provider 内按幂等和成本规则做至多一次有界重试；不得自动把同一图片依次发送给其他 Provider。切换 Provider 或升级高成本模型必须由家长明确确认，且仍只能发送同一已确认脱敏副本。

云端结果无论置信度高低，P1 都必须由孩子或家长确认/校正后才形成 `VerifiedQuestion`。低置信度、Schema 失败、题目区域不完整或题干/答案无法区分时必须要求校正，不得进入 Tutor、错因或掌握度流程。

### 4. 识别与辅导分离

图片解析和 Tutor 是两次独立调用：

1. 脱敏图片 → 云端视觉解析 → `QuestionExtraction` → 人工确认 → `VerifiedQuestion`。
2. `VerifiedQuestion` + 最少匿名学习上下文 → Tutor Policy → 分步提示/讲解。

第一次调用禁止直接给出面向孩子的完整答案；第二次调用继续受 ADR-0004 的提示层级、Schema、安全和成本门禁约束。

### 5. 生命周期与审计

- 原图和家长保存的单题图继续遵循 ADR-0011/0018；本 ADR 不静默修改已接受的 24 小时、7 天和 30 天默认值。
- `sanitized_derivative` 是临时受限对象：云端响应完成后立即删除；失败时最多保留 24 小时用于同一 Provider 的有界重试或人工检查，且不得被家长“长期保存”。
- Provider 只接收内存字节或一次请求内的受控上传，不接收可长期访问的 MinIO URL。
- 审计记录脱敏规则版本、检测类型枚举/数量、用户确认、脱敏副本不可逆哈希、Provider/模型/Prompt/Schema、延迟、token/成本、结果和删除状态；不记录原图、脱敏图、敏感 OCR 文本、完整题目或 Provider 原始响应。

真实儿童图片外发前必须批准付费/企业数据条款、训练退出或不用于训练、数据保留、处理区域、子处理方、删除能力、预算和安全联系渠道。开发与评测默认只使用 synthetic 图片。

## Consequences

### Positive

- 云端模型负责其更擅长的公式、几何图、表格、插图和手写结构理解，本地无需维护完整题目解析与结果合并链路。
- 原图不出家庭边界，图片外发前存在裁剪、自动脱敏和用户确认三层防护。
- 识别与讲题分离，错误题目可在 Tutor 前纠正，避免错误继续放大。
- Provider Adapter、固定 Schema、单 Provider 路由和成本门禁保持模型可替换且可审计。

### Negative / Trade-offs

- 核心拍题能力依赖网络和获批云 Provider；云端不可用时只能重试或手工录入。
- 本地仍需轻量 OCR、规则和视觉检测，且必须维护手动涂抹/确认 UX；“自动脱敏”不能宣传为绝对匿名。
- 当前 OCR Job、结果合同、公式模式和中型模型代码与新目标存在迁移成本，短期会同时存在“已实现旧路线”和“未实现新路线”。
- 每张图片增加一次显式确认，延长交互；这是 Restricted 数据外发的必要门禁。

### Risks and Mitigations

- 风险：本地检测漏掉手写姓名、背景人脸或学校特有信息；缓解：单题裁剪、元数据清除、多检测器、实色遮挡、用户确认和低置信度阻断。
- 风险：遮挡题目中的必要内容导致模型误解；缓解：位置/标签上下文规则、脱敏预览、手动调整和云端结果确认。
- 风险：Provider 保存、训练或跨区处理儿童图片；缓解：真实数据前完成条款/区域/子处理方审批，只用获批付费通道并保留立即停用开关。
- 风险：Provider 失败导致重复外发和重复计费；缓解：业务幂等键、单 Provider、至多一次有界重试、预算硬上限和脱敏副本删除状态。

## Compatibility and Migration

- 兼容性：现有 `0.5.0` Capture/OCR 接口、`ocr_jobs`/`ocr_results` 数据和已确认校正记录保持原义；不得把历史本地 OCR 结果重解释成云端视觉结果。
- 迁移步骤：
  1. 先新增 Provider-neutral 的 `PrivacySanitization`、`ImageAnalysisJob`、`QuestionExtraction` 和 `VerifiedQuestion` Schema/状态，不复用含糊的 OCR 字段承载云结果。
  2. 用 synthetic 图片实现/评测 `PrivacySanitizer`，再接入人工预览、手动涂抹和哈希确认门禁。
  3. 完成云 Provider 条款、区域、预算、密钥、固定视觉评测和功能开关审批后，才实现云视觉 Adapter。
  4. 将当前 PaddleOCR 完整解析与 `formula` 模式从默认路由移除；可保留为关闭的回滚/自托管插件，但业务默认只消费其隐私检测坐标。
  5. 新旧 Job 并行兼容一个客户端窗口后，再通过独立 OpenAPI/数据库迁移收缩旧默认路由；删除或重命名字段前必须有迁移与回滚记录。
- 回滚：关闭云视觉功能开关并回到重新裁剪/手工录入；如需临时启用已验证的本地完整 OCR，只能作为不外发的显式回滚 Provider。无论何种回滚都不得发送原图或恢复已删除的脱敏副本。

## Validation

- 用 synthetic 图片覆盖姓名/学校/班级/电话/身份证/地址/签名、人脸、二维码、条形码、教材人物名、教材印刷人脸、无敏感信息、漏检和误遮挡。
- 验证 EXIF/缩略图清除、实色像素覆盖、重新编码后不存在原始像素、用户确认哈希绑定和脱敏副本到期删除。
- 固定云视觉评测覆盖文字、公式、表格、几何图、手写、题干/答案分离、低置信度、Schema 失败、Prompt 注入、超时、单 Provider、重试、成本和人工确认。
- 验证日志、错误、审计、Trace 和评测输出不包含图片、敏感 OCR 文本、完整题目、签名 URL、对象键或 Provider 原始响应。
- 在任何真实儿童图片外发前，由产品、安全/法务和技术 Owner 完成 Provider 数据处理与生产发布门槛审查。
