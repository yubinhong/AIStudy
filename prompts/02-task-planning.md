# Prompt：需求拆解与执行计划

计划对象：`{{PRD_ID_OR_TASK_DESCRIPTION}}`

请先阅读 `AGENTS.md`、`AI_CONTEXT.md`、`PROJECT.md`、相关 `PRD.md`、`ARCHITECTURE.md`、`TESTING.md`、`SECURITY.md` 和现有代码。

本轮只做调查与计划，不修改业务代码：

1. 从入口、调用链、数据模型、接口、测试和部署路径确认当前行为。
2. 明确最小可交付范围、禁止改变的行为、依赖和风险。
3. 将当前执行项写入 `TASK.md`：目标、范围内/外、验收标准、影响面、约束、验证和回滚。
4. 若任务跨模块、高风险或无法在一个短会话完成，更新 `PLANS.md`，按可独立验证的里程碑拆分；每个里程碑写清输出、文件、验证和检查点。
5. 范围外发现进入 `TODO.md`，不要混入当前实施计划。
6. 对不可逆架构选择提出 ADR 建议；不要未经批准直接定案。

计划必须具体到另一位工程师可以直接执行，避免“完善功能”“处理异常”这类模糊步骤。

最终输出：推荐方案、涉及文件、阶段计划、验证命令、风险/回滚、仍需确认的唯一阻塞问题。若无阻塞，将 `TASK.md` 状态设为 `READY`。
