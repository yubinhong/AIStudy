# API

FastAPI modular-monolith entrypoint for the study assistant. The repository
also provides native `linux/amd64` release and `linux/arm64` development images, plus an `infra/compose` deployment with
PostgreSQL migrations, MinIO, the parent Web and a durable NewAPI
image-analysis worker. See
`infra/compose/README.md` for the self-hosted deployment procedure.

The current P0 slice exposes `/healthz` and Household-scoped routes. All
Household routes require a revocable session created by `/auth/login` with a
username and password. Web sends the session as an HttpOnly cookie; Flutter
sends the same opaque session type as a Bearer token.

Example local request:

```bash
curl -H 'Authorization: Bearer <opaque-session-from-auth-login>' \
  http://localhost:8000/households/00000000-0000-0000-0000-000000000001/children
```

amd64 模型镜像构建需要提供 `ocr-model-manifest.json` 中的官方归档和摘要；构建脚本会拒绝空摘要、非 HTTPS 来源、路径穿越、软链接以及缺少模型目录的归档。运行层包含 PaddleOCR/OpenCV/CPU runtime 所需的最小 `libgl1`、`libglib2.0-0`、`libgomp1` 系统库。

Apple Silicon 可在 macOS 原生 Python 环境安装锁定的 PaddlePaddle/PaddleOCR。Docker Desktop 的容器是 Linux ARM64；由于 PaddlePaddle 3.3.1 没有 Linux aarch64 wheel，`linux/arm64` 调试镜像会跳过 Paddle 依赖和模型，只保留 API、迁移与 NewAPI ImageAnalysis 能力。旧本地 OCR/依赖 Paddle 的隐私检测需要在 macOS 原生进程中调试，或显式使用较慢的 `linux/amd64` 模拟镜像。

Ubuntu 24.04 CPU 真实模型评测前先运行只读预检；预检不会下载模型、读取图片或启动推理：

```bash
PADDLE_MODEL_ROOT=/opt/study/models \
./.venv/bin/python scripts/check_ocr_runtime.py
```

宿主运行时只有 Ubuntu 24.04 输出 `status=ready` 才允许继续真实模型评测；amd64 发布镜像使用已锁定的 Debian 13 slim 运行层，镜像内显式设置 `STUDY_OCR_CONTAINER_RUNTIME=true` 后可通过同一预检。该选项不放宽 Linux、x86_64、Python 3.12、Paddle 版本或五份构建期模型标记检查。评测数据必须是经授权的合成或脱敏样本，真实儿童图片不得进入仓库、日志或评测输出。

## Local commands

```bash
uv sync --locked
uv run ruff format --check .
uv run ruff check .
uv run pytest -m "not integration"
uv run uvicorn study_api.main:app --reload
# With local Postgres/MinIO and pre-provisioned models, start the API in the
# same durable mode as the Worker:
STUDY_API_LEARNING_REPOSITORY=postgres \
STUDY_API_OCR_QUEUE=postgres \
STUDY_API_OCR_RESULTS=postgres \
uv run uvicorn study_api.main:app --host 0.0.0.0 --port 8000

# Process one queued job and exit:
STUDY_API_OCR_QUEUE=postgres uv run python scripts/run_ocr_worker.py

# Or keep polling the durable queue until Ctrl-C:
STUDY_API_OCR_QUEUE=postgres OCR_WORKER_POLL_INTERVAL_SECONDS=2 \
uv run python scripts/run_ocr_worker.py --watch

# Self-hosted NewAPI image analysis (only after explicit configuration):
STUDY_API_LEARNING_REPOSITORY=postgres \
STUDY_API_IMAGE_ANALYSIS_REPOSITORY=postgres \
STUDY_NEWAPI_ENABLED=true \
STUDY_NEWAPI_USER_AGENT=study-api/0.5 \
uv run python scripts/run_image_analysis_worker.py --watch

# Run one synthetic live NewAPI check; it cleans up its own database rows and object.
uv run python scripts/run_newapi_live_eval.py
```

`uv.lock` is generated by the approved toolchain bootstrap and must be checked
in before this subproject is considered runnable. The Docker image copies
`migrations/`, `alembic.ini` and `scripts/` so the Compose `migrate` and
`image-analysis-worker` services use the same locked runtime as the API. The
worker is safe to start by default: when `STUDY_NEWAPI_ENABLED=false`, it stays
idle without constructing a Provider client or reading images.

Provider failures are reduced to stable error codes such as
`provider_http_403`, `provider_network_error`, `provider_timeout`, and
`provider_response_schema_invalid`; raw response bodies are not logged or
persisted.

The adapter sends `Accept: application/json` and a configurable,
printable-ASCII `STUDY_NEWAPI_USER_AGENT` (default `study-api/0.5`). This
avoids Cloudflare rules that reject Python's default `urllib` signature; the
value is bounded to prevent header injection.

Copy the local-only storage variables from the repository `.env.example` into
your local environment before using Capture uploads. If they are absent, the
API deliberately keeps non-upload routes available but rejects upload issuance
without falling back to embedded credentials.
